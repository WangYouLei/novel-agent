# NovelAgent 产品需求文档 (PRD)

> 版本：v0.2
> 日期：2026-10-08
> 状态：讨论稿

## 1. 文档概述

本文档定义 NovelAgent 小说创作 Agent 的产品需求，包括产品定位、核心概念、功能范围、业务规则与 MVP 验收标准。

**设计原则**：
- **优先简单**：不为一次性需求创建抽象，不为未知的未来过度设计
- **精准修改**：每一项功能都有明确的存在理由，可追溯到具体用户需求
- **可演进**：MVP 阶段做减法，但产品架构上为未来扩展预留空间

---

## 2. 产品定位

### 2.1 产品是什么

NovelAgent 是一个**可插拔的 AI 小说创作平台**。核心能力由一个个独立的功能插件提供，用户可以根据自己的创作需求，像搭积木一样选择、组合、扩展创作能力。

### 2.2 目标用户

| 用户类型 | 特征 | 核心诉求 |
|----------|------|---------|
| 网络小说作者 | 有写作经验，需要效率工具 | 快速生成大纲、角色设定、润色改写，突破卡文 |
| 业余写作爱好者 | 想写但不会写，需要引导 | 从零开始一步步引导创作，降低门槛 |
| 高级玩家 / 开发者 | 懂技术，想定制自己的创作流程 | 自定义模型、自定义风格、开发自己的功能插件 |

### 2.3 核心价值

1. **灵活可扩展**：创作能力以插件形式存在，想用什么装什么，不想要的可以卸掉
2. **风格个性化**：支持多种风格来源（内置/自定义生成/第三方），每个人都能找到适合自己的写作风格
3. **创作辅助全流程**：从创意萌芽、世界观设定、角色塑造、大纲规划到逐章写作，全链路覆盖
4. **低门槛 + 高上限**：新手开箱即用，高手可以深度定制

## 3. 核心概念

### 3.1 功能插件

功能插件是**可独立安装、卸载、启用、禁用的创作能力单元**。

**性质**：
- 每个插件提供一项具体的创作功能（如大纲生成、角色管理、润色、续写）
- 有独立的版本号、作者、依赖声明
- 通过插件市场分发（未来）
- 插件之间可以有依赖关系（如大纲生成插件依赖模型能力）

### 3.2 模型提供者

AI 模型的提供方。分为两类：

| 类型 | 说明 | 计费方式 |
|------|------|---------|
| 内置免费模型 | 平台提供的模型服务 | 消耗积分，每日可领取免费积分，VIP 有额外权益 |
| 用户自定义模型 | 用户自己配置的模型厂商（如 OpenAI、Claude、本地模型等） | 用户用自己的 API Key，平台不收费 |

> 模型提供者的实现形式（插件化/内置）属于技术设计范畴，不在本需求文档中展开。

### 3.3 风格包

风格包是**描述写作风格的数据集合**，影响 AI 生成内容的风格倾向。

**三级供给体系**：

| 层级 | 来源 | 可修改性 | 说明 |
|------|------|---------|------|
| 内置风格包 | 系统预置 | 只读（可复制后修改） | 开箱即用，保证任何功能都有兜底风格可用 |
| 用户生成风格包 | 通过风格生成功能产出 | 用户可修改 | 用户从已写章节、参考小说等多种来源提取生成 |
| 第三方风格包 | 从市场下载 | 用户可修改 | 第三方发布的风格数据包 |

**风格生成方式多样**：
- 从已写的小说章节中提取
- 从用户上传的参考小说中提取
- 混合多源生成（参考小说 + 已写章节）
- 从图片/视频文案等其他来源提取（未来扩展）

**一本小说一个主体风格包**：用户为每本小说选择一个主风格包，作为全局默认。

> 📌 **未来扩展点（预留，MVP不实现）**
>
> **场景级风格覆盖**：长远看，用户可能希望"打斗场景用A风格，情感场景用B风格"。
> 当前以小说级为主风格，后续可扩展到章节级、场景级覆盖。

### 3.4 风格生成功能

生成风格包的功能。有两种实现层级：

| 层级 | 内容 | 说明 |
|------|------|------|
| 基础提取（内置） | 从文本中提取风格 | 保证开箱即用，新用户不用装任何功能就能生成风格包 |
| 高级提取（功能插件） | 多源混合、视频文案提取、统计特征法等 | 满足进阶需求，可通过插件生态扩展 |

### 3.5 插件与风格包的关系

功能插件通过**风格需求声明**来描述自己与风格包的关系，系统按优先级解析：

| 优先级 | 条件 | 行为 |
|--------|------|------|
| 1 | 插件完全自己处理风格 | 跳过风格包机制 |
| 2 | 用户选的风格与插件兼容 | 使用用户选择的风格包 |
| 3 | 不兼容 + 插件有内置兜底风格 | 使用插件内置兜底风格，UI 软提示"当前风格与插件不完全匹配" |
| 4 | 不兼容 + 插件必须要特定风格 + 无兜底 | 功能不可用，UI 提示"此功能需要 XX 风格包，点击安装/生成" |
| 5 | 插件偏好风格 + 无兜底 | 降级使用用户当前风格，UI 提示"效果可能打折" |

**设计思想**：永远有清晰的反馈，不静默失败。软引导优先于硬阻断。

## 4. 功能范围

### 4.1 功能模块总览

| 模块 | 子功能 | 说明 | MVP |
|------|--------|------|-----|
| **创作核心** | 大纲生成 | 根据一句话创意生成完整小说大纲 | ✅ |
| | 章节写作 | 根据大纲逐章生成正文 | ⏸️ |
| | 续写 | 选中一段文字，AI 继续往下写 | ⏸️ |
| | 润色改写 | 调整文字风格、优化表达 | ⏸️ |
| | 对话生成 | 生成符合人物性格的对话 | ⏸️ |
| **设定管理** | 角色档案管理 | 角色信息、关系网、成长轨迹 | ⏸️ |
| | 世界观设定管理 | 势力、地点、物品、功法、时间线 | ⏸️ |
| | 设定一致性检查 | 检查前后文设定是否矛盾 | ⏸️ |
| **风格系统** | 风格包管理 | 查看、选择、复制、修改、删除风格包 | ✅ |
| | 基础风格提取 | 从文本中提取生成风格包 | ⏸️ |
| | 高级风格生成插件 | 多源、多方式生成风格包 | ⏸️ |
| **插件系统** | 插件管理 | 安装、卸载、启用、禁用、查看详情 | ✅ |
| | 插件配置 | 调整插件参数 | ✅ |
| | 依赖检测 | 检测插件依赖是否满足，缺失时提示 | ✅ |
| | 插件市场（预留） | 浏览、搜索、下载第三方插件 | ⏸️ |
| **模型系统** | 内置免费模型 | 平台提供的模型，消耗积分 | ✅（mock） |
| | 自定义模型配置 | 用户配置自己的模型厂商 API | ✅ |
| | 模型选择与切换 | 创作时选择使用哪个模型 | ✅ |
| **账户与计费** | 用户注册登录 | 用户名密码登录，业务数据关联用户 | ✅ |
| | 积分体系 | 积分获取、消耗、流水记录 | ✅（mock） |
| | VIP 会员 | VIP 权益、到期管理 | ⏸️ |
| | 每日领取 | 每日免费积分领取 | ✅（mock） |
| **小说管理** | 小说列表 | 创建、编辑、删除小说 | ✅ |
| | 章节管理 | 章节列表、增删改查 | ⏸️ |
| | 章节版本历史 | 历史版本、对比、回滚 | ⏸️ |
| | 创作历史 | 查看历史创作记录 | ⏸️ |

> **MVP 说明**：标注 ✅ 的为 MVP 必做，标注 ⏸️ 的为后续迭代做。

> **单机版与登录体系的关系**：MVP 以单机部署为主（见技术设计文档第 9 节）。登录体系的意义在于预演"多用户数据隔离"的完整链路：单机场景下通常只有一个本地账号，但所有业务数据（小说、插件、积分）均按用户隔离存储，确保未来服务端多用户部署时不做结构性返工。

> 📌 **未来扩展点（预留，MVP 不实现）**
>
> **章节版本历史**：每次保存章节正文时留存历史版本，支持版本对比与回滚。
> 实现考虑：独立的 `chapter_version` 表（存章节快照）或章节表上增加单版本回滚字段（轻量方案）。
> MVP 不实现，但数据层设计预留扩展空间（不因加版本表而破坏现有结构）。

### 4.2 插件配置

每个功能插件可以声明一组可配置参数，用户在 UI 上调整这些参数来改变插件行为。

例如大纲生成插件可以配置：
- 小说篇幅（短篇/中篇/长篇）
- 剧情转折频率
- 章节数量
- 是否包含伏笔设计

配置参数由插件自己声明 schema，UI 根据 schema 动态渲染表单。

### 4.3 生成限制

- 单次批量生成任务最多生成 **10 章**（服务端可配置参数，非写死）
- 目的：
  1. 成本保护——单次调用的积分/Token 消耗有上限
  2. 防止用户积分被一次性烧完
  3. 保证生成质量——批量上下文过长时生成质量明显下降
- 未来可按用户分层（如普通用户 10 章、VIP 20 章），作为运营手段

## 5. 核心业务流程

### 5.1 插件使用流程

```
用户打开插件管理页
  → 看到所有已安装的插件列表
  → 可以启用/禁用插件
  → 可以点击配置，调整插件参数
  → 禁用的插件在创作功能中不可见
```

### 5.2 大纲生成流程（MVP 核心链路）

```
用户创建一本小说
  → 选择主体风格包（不选则用默认）
  → 进入大纲生成功能
  → 输入创意一句话描述
  → 选择使用的模型（内置/自定义）
  → 调整大纲生成插件的参数（可选）
  → 点击生成
  → 系统调用大纲生成插件
    → 插件调用模型提供者
    → （内置模型）扣费校验 → 调用模型 API → 记录调用
    → （自定义模型）直接调用用户配置的 API
  → 返回大纲结果
  → 用户可以保存大纲到小说
```

### 5.3 风格包使用流程

```
用户为小说选择风格包
  → 可选来源：内置风格包 / 我的风格包 / 第三方风格包
  → 选中后设为小说的主体风格
  → 创作功能自动使用该风格包

用户生成自定义风格包
  → 选择生成方式（基础文本提取/插件提供的其他方式）
  → 输入源材料（已写章节/上传文本/其他）
  → 点击生成
  → 生成成功后出现在"我的风格包"中
  → 用户可以修改、重命名、应用到小说
```

### 5.4 插件依赖关系

- 插件可以声明依赖其他插件或系统服务
- 依赖不满足时，插件不可用，但不影响其他插件
- UI 清晰提示缺失的依赖，并引导用户安装
- 支持可选依赖：缺少可选依赖时插件可用，但部分功能受限

## 6. MVP 范围与验收标准

### 6.1 MVP 目标

验证**可插拔创作平台**的核心产品假设：插件框架能跑起来，功能插件能提供实际创作价值，用户能感知到"插拔"的灵活性。

### 6.2 MVP 功能清单

| 模块 | 功能 | 说明 |
|------|------|------|
| 插件系统 | 插件加载/卸载/启用/禁用 | 核心能力 |
| 插件系统 | 插件依赖解析（缺失提示） | 核心能力 |
| 插件系统 | 插件配置参数调整 | 验证插件可定制性 |
| 模型系统 | 内置免费模型（mock 实现） | 验证混合模式 |
| 模型系统 | 自定义模型插件（至少一个示例） | 验证模型插件化 |
| 风格系统 | 内置风格包（3-5个） | 验证风格包机制 |
| 风格系统 | 风格包查看与选择 | MVP 最小可用 |
| 创作功能 | 大纲生成插件 | 核心示例功能插件 |
| 小说管理 | 小说创建与列表 | 基础数据载体 |
| 账户系统 | 用户注册登录（用户名密码） | MVP 确认要做，所有业务数据关联用户 |
| 积分系统 | mock 积分（无真实计费） | 验证流程 |
| 前端 | 插件管理页 | 验证插件管理交互 |
| 前端 | 大纲生成演示页 | 验证端到端创作流程 |
| 示例插件 | plugin-outline-gen（大纲生成） | 功能插件示例 |
| 示例插件 | plugin-openai-model（OpenAI 模型） | 模型插件示例 |

### 6.3 MVP 验收标准

1. **插件加载**：启动应用 → 系统扫描插件目录 → 成功加载 2 个示例插件
2. **插件管理**：插件管理页显示已加载插件列表，可启用/禁用，状态实时刷新
3. **插件配置**：点击插件配置，能看到插件声明的参数，修改后生效
4. **端到端创作**：创建小说 → 选择风格包 → 进入大纲生成 → 输入创意 → 生成大纲 → 保存成功
5. **依赖机制**：禁用模型插件后，大纲生成功能不可用，UI 清晰提示"缺少模型提供者"
6. **风格差异**：选择不同风格包生成大纲，输出内容风格有明显差异
7. **自定义模型**：用户配置自己的 OpenAI API Key 后，大纲生成可走自定义模型，不消耗积分

## 7. 待讨论事项

- [x] MVP 用户系统 → 确认要做登录（用户名密码），所有业务数据关联用户
- [x] 模型调用记录存储 → 只存摘要（输入/输出各 500 字）+ token 数，保留 90 天定期清理
- [x] 单次生成上限 → 10 章（服务端可配置），见 4.3
- [ ] 内置免费模型的积分定价策略（产品决策：生成一次大纲扣多少分，每日领多少）
- [ ] 插件市场的形态（什么时候做、做多重）
- [ ] 章节正文全文是否长期存储（调用日志已定摘要化，章节正文当前存数据库）
